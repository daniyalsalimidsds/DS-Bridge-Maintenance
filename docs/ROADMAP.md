# Project Roadmap

This roadmap records planned repository work. It is not a promise of external adoption or a substitute for release notes.

## Current stable line

**v1.6.x**

Focus:

- preserve release integrity and backward compatibility,
- fix reproducible defects,
- improve documentation and field usability,
- maintain Android compatibility and reporting reliability.

## v1.7.0 — active development

The current development line prioritizes safety-critical workflow and data-integrity improvements already tracked in the changelog.

Main themes:

- draft / submit / independent QC / approval workflow,
- authenticated local user identity and role controls,
- stronger signature and inspector traceability,
- explicit critical-finding lifecycle and follow-up,
- immutable or auditable history for submitted records,
- inspection scheduling and due-date logic,
- professional-qualification metadata,
- fail-safe severity migration,
- collision-resistant report numbering,
- stronger tamper detection and export validation.

Implementation details and completed checkpoints are recorded in [CHANGELOG.md](CHANGELOG.md).

## Validation priorities

Before treating a future release as production-ready, the project aims to strengthen:

- physical-device testing,
- camera and GPS field testing,
- upgrade/migration testing from prior releases,
- accessibility and RTL regression coverage,
- report rendering across realistic long-content cases,
- reproducible release verification.

## Open-source growth priorities

The project welcomes legitimate external participation. Near-term repository goals include:

- clearer English documentation,
- reproducible issue templates,
- contribution and review guidance,
- engineering-review feedback,
- device-compatibility reports,
- field-validation feedback using non-sensitive or synthetic data.

Community metrics will not be fabricated or inflated; adoption claims should be backed by public evidence.
